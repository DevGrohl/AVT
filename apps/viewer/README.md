# AVT Viewer

Static/local web viewer for AVT Execution Flow Graph JSON.

The viewer runs entirely in the browser. It does not require a backend and does not upload graph files.

## Stack

- Vite
- React
- TypeScript
- React Flow (`@xyflow/react`)

Visualization choice is documented in `docs/adr/0003-use-react-flow-for-phase-1-viewer.md`.

## Install

From `apps/viewer`:

```sh
npm install
```

## Run locally

```sh
npm run dev
```

Open the local URL printed by Vite.

## Production build

```sh
npm run build
npm run preview
```

Build output is written to `dist/`.

## Load a graph

The viewer loads `public/sample-graph.json` by default.

To load a graph generated by the analyzer:

1. Run the analyzer:

   ```sh
   uv run --project packages/analyzer avt analyze . --no-timestamp --out /tmp/avt-graph.json
   ```

2. Start the viewer:

   ```sh
   cd apps/viewer
   npm run dev
   ```

3. Click **Load graph JSON**.
4. Select `/tmp/avt-graph.json` or another generated graph file.

Optional Phase 2 Guide file:

```sh
uv run --project packages/analyzer avt guide-entrypoints . --out /tmp/avt-guide.json
```

Click **Load guide JSON** to show Guide observations, suggested Entry Points, confidence, reasons, and risks in the sidebar.

## UI guide

### Graph summary

The left panel shows:

- project name;
- schema version;
- analyzer version;
- Entry Point count;
- Execution Flow count;
- warning count;
- secret warning count.

### Entry Point / Group selector

Use **Selected Entry Point / Group** to choose what to inspect. The default selected flow is ranked for likely usefulness instead of simple alphabetical order.

The selector includes:

- individual Entry Points;
- grouped Entry Points by kind, such as `All web_route Entry Points` or `All framework_hook Entry Points`;
- grouped web route options by directory, such as `All web routes in app/api/endpoints/*`;
- grouped web route options by file, such as `All web routes in app/api/endpoints/users.py`.

Grouped options combine nodes, edges, and markers from all matching Entry Point flows. This is useful for API projects where a Developer wants to see all endpoints under one folder at once.

The viewer still avoids rendering the whole project graph by default; it renders the selected Entry Point or selected Entry Point group.

### Graph canvas

The main panel renders the selected Execution Flow with React Flow.

Visible node types include:

- `module`;
- `class`;
- `function`;
- `method`;
- `external`.

Visible edge types include:

- `call`;
- `await`;
- `external_interaction`.

Hierarchy context is shown by including ancestor module/class nodes for visible flow nodes.

Use **Diagram layout** to switch how the same selected flow is drawn:

- **Nested ownership map** — modules/classes are container areas that own their functions/methods.
- **Swimlane hierarchy** — each module becomes a horizontal lane; classes/functions sit inside the lane to reduce overlap.
- **Outline + focused graph** — hierarchy becomes a compact left outline while behavior nodes remain in the main flow graph.
- **Layered flow** — flow-oriented view. Places roots on the left and reachable calls/interactions in later columns while keeping module/class context as container swimlanes when context is enabled. Layout changes force a fresh fit-to-view.
- **Circular relationships** — relationship overview for spotting clusters/cycles in dense graphs.
- **Compact grid** — dense scan-friendly layout when labels/lists matter more than edge geometry.

Use **Diagram handling** to tune what the diagram shows:

- show/hide module/class context nodes;
- show/hide External Interactions;
- switch edge labels between kind, reason, or none.

The graph canvas is intentionally larger than the text details area because visual exploration is the primary product interaction.

Diagrams are editable in the current browser session: drag nodes to adjust the layout. Select a module or class and use the Inspector's container size controls to make it wider/narrower/taller/shorter. Moved positions and container sizes are remembered per selected flow/layout/handling combination until a new graph is loaded or **Reset layout** is clicked.

These options are inspired by database diagram tools such as DataGrip: the graph data stays the same, but layout and handling change depending on what the Developer is trying to understand.

### Inspector

Click a graph node or edge to populate the inspector in the left panel.

Node inspector shows:

- kind;
- label;
- path when available;
- qualified name when available;
- signature when available;
- Flow Markers attached to the node.

Edge inspector shows:

- kind;
- certainty;
- evidence reason;
- source location.

### Guide suggestions

The left panel can load a Phase 2 Guide JSON file generated by `avt guide-entrypoints`. The Guide panel shows:

- project observations;
- suggested Entry Points;
- confidence;
- reason;
- risk;
- **Show flow** buttons for suggestions that match the loaded graph.

This keeps LLM/Guide recommendations visible next to the deterministic graph without mixing unvalidated suggestions into graph facts. Clicking **Show flow** selects the matching deterministic Entry Point flow.

### Edge filters

The left panel includes filters for edge certainty:

- **Confirmed** — edges the analyzer believes are statically supported.
- **Uncertain** — possible edges the analyzer cannot prove.
- **Rejected** — edges rejected by an Analysis Overlay.

Rejected edges are hidden by default.

### Flow details

Below the graph canvas, the viewer has a collapsed **Visible details** section with a small preview of nodes and edges. The visual graph is the primary interaction surface; use the details section only when you need a text fallback or quick preview.

## Graph JSON expectations

The viewer expects the analyzer's Execution Flow Graph shape:

```json
{
  "metadata": {},
  "entry_points": [],
  "flows": [],
  "nodes": [],
  "edges": [],
  "markers": [],
  "warnings": []
}
```

The viewer performs a lightweight shape check when loading files. It is not a full schema validator.

## Current behavior

Implemented:

- load bundled sample graph;
- load graph JSON with local file picker;
- select individual Entry Points or grouped endpoint flows;
- render selected Execution Flow with React Flow;
- include hierarchy ancestor context with hierarchy-aware layout;
- style External Interactions and certainty states;
- filter confirmed/uncertain/rejected edges;
- inspect nodes and edges;
- show Flow Marker counts/details;
- show warning and secret warning counts.

Not implemented yet:

- Analysis Overlay editing/export from the viewer;
- source-code snippets;
- editor deep links;
- automated browser tests;
- advanced layout tuning for very large flows.
